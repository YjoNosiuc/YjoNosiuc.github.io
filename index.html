KMSAR

Knowledge Management System for Academic Research, Angeles University Foundation

Problem
Faculty research records for the research office (OVPRI), CDAIC, and CCS were scattered, and approvals were tracked manually.
Key features
Research registration, a multi-stage approval flow through the dean and OVPRI, document uploads, and bulk import of faculty accounts.
Tech
LaravelPHPPlaywright
Read case study

What I worked on

I built the whole system on my own: the database, the approval workflow, the pages for each type of user, and the bulk import so the office didn’t have to create faculty accounts one by one.

How it was tested

  • Automated end-to-end tests with Playwright covering each user role.
  • User acceptance testing with testers from different colleges. I sorted their feedback by priority and worked through it before the pilot.
  • A pilot demo with deans and OVPRI staff, plus a user manual for non-technical users.

What I learned

Real users find problems that tests don’t. Watching people use the system taught me to write clearer screens, better error messages, and documentation people can actually follow.

GANAP PH

Event registration system for barangays

Problem
Barangay events are usually announced on paper or social media, with no easy way for residents to sign up or for officials to control slots.
Key features
Residents browse barangay events and register online. Remaining slots update in real time, paid events go through online checkout, and automations handle follow-up tasks.
Tech
LaravelVueInertia.jsLaravel EchoStripeMake.comPlaywright
Read case study

What I worked on

Full-stack development and the integrations: real-time slot updates, online payments, and workflow automation. I learned most of these tools while building the project.

Problems I worked through

  • Payments: the payment provider’s confirmations were being blocked by the app’s form security. Moving the webhook to the API routes fixed it.
  • Real-time slots: the private live channel kept failing authentication, so I switched to a public broadcast channel for slot counts, since they aren’t sensitive data.
  • Testing: end-to-end tests failed on the built-in development server because it handles one request at a time, so I ran them on Apache instead.
  • Automation: compared Zapier and Make.com and chose Make.com, since its webhook trigger works on the free plan.

What I learned

How webhooks and real-time broadcasting work in practice, and that reading error messages carefully and testing one change at a time saves hours.

FAST Track

AUF Registrar document request and tracking system

Problem
Students had to request academic documents in person and couldn’t see where their request stood.
Key features
Online document requests, clearance approvals across offices, status tracking, generated PDF documents, and OTP or Google sign-in.
Tech
LaravelBladeAlpine.jsMySQLdompdf
Read case study

Problems I worked through

  • Disappearing errors: form error messages vanished when the front-end script reloaded, so I moved them outside the interactive components.
  • PDF output: the PDF library couldn’t display the peso sign, so I changed fonts and formatting.
  • Stronger tests: learned that checking a page isn’t “forbidden” isn’t enough. Tests should confirm the action actually succeeded.

Evaluation and publication

Evaluated with the Technology Acceptance Model and ISO quality criteria through a survey of IT experts. Our paper on the system was accepted at the IEEE ITIS 2026 conference (October 14–16, 2026), a Scopus-indexed conference, and the project was endorsed by our adviser for final defense.

What I learned

Working in a team of four meant agreeing on structure early and keeping documentation in sync with the real setup, which saved us a lot of debugging.

How I approach a project

The process I try to follow, and keep improving.

1

Understand the need

Talk to the people who will use it and write down what they actually need before building.

2

Build in small steps

Plan the database and screens, then build one feature at a time so problems are easy to trace.

3

Test as I go

Write automated tests for the important flows so changes don’t break what already works.

4

Listen and improve

Let real users try it, collect their feedback, and fix what matters most first.
